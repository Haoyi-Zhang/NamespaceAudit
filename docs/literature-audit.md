# Full-paper literature audit and venue calibration

## Method and counting rule

This audit supports the internal TDSC-oriented draft; it is not a systematic review, a citation ranking, or an external novelty certificate. A paper is counted as a *full-paper calibration item* only when all of the following were checked on 2026-09-18:

1. journal/conference identity, author list, year, pagination, and DOI were reconciled against a publisher, DBLP, or institutional record;
2. a complete publisher HTML article, author manuscript, accepted manuscript, or open full PDF was available;
3. the introduction/problem statement, model or assumptions, principal construction/theorem, evidence section, limitations/conclusion, and reference list were inspected;
4. the lesson recorded below is structural or technical rather than copied wording.

Reference-list size is recorded as a transparent bin because PDF text extraction sometimes merges or splits entries: **small** is fewer than 25 entries, **medium** is about 25--50, and **large** is more than 50. Figure/table roles are descriptions of how evidence is carried, not exact counts. Abstract-only pages and search snippets are not counted. Full texts are not redistributed in the artifact; stable scholarly or institutional locations and access notes are retained in `external_resources.csv`.

### Venue-pattern synthesis

The 12 papers share a useful TDSC narrative without imposing one outline: a concrete dependability/security failure motivates an explicit model; the mechanism is followed by the strongest appropriate argument (proof, lower bound, verification, or protocol invariant); implementation or finite evidence is described separately; and figures/tables carry either semantic structure or measured comparisons. The draft therefore keeps nine main sections, places the model and exact criterion before the checker, labels finite validation as implementation evidence, and reserves one limitations/integration section instead of scattering disclaimers.

## Resulting novelty boundary

The closest sources already cover self-certifying names, signed forwarding, quorum intersection, bounded compromise windows, online reconfiguration, recovery event precedence, key transparency, and consensus accountability. The retained contribution must therefore remain narrow and explicit: an exact static criterion for jointly certifiable **incompatible** finite namespace views under supplied recovery order, monotone authorization policies, graph dependencies, and a shared downward-closed exposure family; a strict nonlocal composition example; an exact exposure-capacity margin with Hall obstruction certificates; a complexity boundary; and a bounded checker plus independently implemented replay. This audit does not certify novelty by itself; human authors must repeat the source review before external use.
